## 1. 목표와 범위

Android 휴대폰으로 야외 달리기를 기록한다. 앱은 사용자가 달린 것으로 **측정된 구간**을 지도에 표시하고, 그 동일한 구간에서 거리와 페이스를 계산한다. GPS가 실제 경로를 알려주지 못한 구간은 경로와 거리로 꾸며 넣지 않는다.

- 포함: 달리기 시작·수동 일시정지·재개·종료, 현재 위치와 경로 지도, 측정 거리, 경과 시간, 현재 페이스, 측정 구간 평균 페이스, 기록 목록·상세, 원본 GPS 영구 저장, 비정상 종료 뒤 기록 복구.
- 제외: 자전거, 자동 일시정지, 도로에 좌표를 강제로 붙이는 지도 매칭, 신호 공백의 거리 추정, 칼로리·걷기/뛰기 자동 분류, 계정·서버 동기화.
- 새 앱은 기존 앱과 별도 `applicationId`를 사용해 동시에 설치 가능하게 한다. 기존 앱의 기록을 새 앱으로 이관하는 기능은 이번 범위에 넣지 않는다. 기존 앱과 그 데이터는 건드리지 않는다.

## 2. 사용자에게 보이는 값의 정의

| 값 | 정의 및 표시 규칙 |
|---|---|
| 측정 거리 | 연속성과 품질이 확인된 경로 구간의 길이 합. GPS 공백·수동 일시정지 사이를 잇는 직선은 더하지 않는다. |
| 경과 시간 | 시작부터 종료까지의 실제 시간. 일시정지와 GPS 공백도 포함한다. |
| 운동 시간 | 경과 시간에서 **수동 일시정지 시간만** 제외한다. 자동 일시정지가 없으므로 서 있던 시간은 포함한다. |
| 측정 구간 시간 | 거리 계산에 사용된 연속 구간의 시간 합. GPS 공백과 수동 일시정지는 포함하지 않는다. 정지 중 유효한 GPS를 받은 시간은 포함한다. |
| 현재 페이스 | 최근의 신뢰 가능한 이동 구간으로 계산한 분/km. 시작 직후·정지 중·신호 불량 중에는 `—` 또는 `측정 중`으로 표시한다. GPS 한 점의 `speed`를 그대로 표시하지 않는다. |
| 측정 구간 평균 페이스 | 측정 구간 시간 ÷ 측정 거리. GPS 공백이 있을 때 전체 달리기의 평균인 것처럼 부르지 않는다. 거리가 0이면 표시하지 않는다. |

GPS 공백이 생기면 화면과 기록 상세에 `GPS 미측정 구간 있음`을 표시한다. 지도는 공백 앞뒤를 실선으로 연결하지 않는다. 공백의 길이나 그동안 이동한 거리를 추측해 총계에 섞지 않는다. 신호 상태가 불량할 때 측정 거리 숫자가 멈추는 것은 정상이며, 회복 후 그 공백을 한 번에 더하지 않는다.

## 3. 데이터 흐름과 단일 계산 규칙

```
Android 위치 콜백
  → 원본 관측을 시각 순서로 저장
  → 순수 Kotlin 경로 엔진에 입력
  → 판정: 유효 구간 / 정지 잡음 / 품질 불량 / 비정상 점프 / 시간 공백
  → 구간별 경로점·거리 증가분·측정 구간 시간·신호 상태 생성
  → 동일한 결과로 실시간 지도·거리·km 표시·페이스 갱신
  → 종료 시 같은 엔진으로 저장된 원본을 재생하여 결과 확정
```

실시간 처리와 종료 후 계산에 서로 다른 알고리즘을 두지 않는다. 경로 엔진은 Android `Location`, UI, Room에 의존하지 않는 순수 Kotlin 모듈로 만든다. 엔진 입력과 출력은 다음처럼 분리한다.

- 입력 `RawFix`: 위도·경도, GPS 측정 시각, 단조 시계 시각, 수평 정확도 유무와 값, 속도 유무와 값, 속도 정확도 유무와 값, 제공자, 수신 시각.
- 출력 `TrackEvent`: 원본 관측 ID, 판정 이유, 표시할 경로점 여부, 새 구간 시작 여부, 거리 증가분, 유효 시간 증가분, 신호 상태.
- `TrackSegment`: 이어 그릴 수 있는 점들의 묶음. 지도는 세그먼트별로 별도 선을 그린다. 거리도 **각 세그먼트 안의 인접한 유효 점 사이에서만** 계산한다.
- 수동 일시정지·재개 이벤트도 원본 기록과 함께 저장한다. 재개 후 첫 점은 새 세그먼트의 시작점이며, 이전 세그먼트와의 거리는 0이다.

### 3.1 GPS 판정 원칙

1. 한 콜백에 도착한 위치 여러 개를 **중복까지 포함해 먼저 원본으로 모두 저장**한다. 경로 엔진에 넣을 때만 단조 시계로 정렬하고 중복·역전 시각을 계산 대상에서 제외한다. 원본 ID와 제외 이유를 남긴다.
2. 위경도 범위, 시각의 신선도, 정확도 존재 여부와 크기, 이동 속도의 물리적 가능성을 확인한다. `accuracy` 한 값만으로 좌표를 채택하지 않는다.
3. 최근 여러 점의 움직임과 정확도를 비교해 한 점짜리 점프와 제자리 GPS 배회를 구분한다. **유효한 정지 상태**에서는 세그먼트를 유지하면서 거리만 0으로 하고 측정 구간 시간과 운동 시간은 계속 흐른다. **GPS 품질 불량 상태**에서는 세그먼트를 끊고 측정 구간 시간도 늘리지 않는다. 정지 잡음 제거는 자동 일시정지가 아니다.
4. 품질이 부족한 점은 원본에 남긴다. 그 점이 다음 거리 계산의 무조건적인 기준점이 되지 않게 한다. 연속성을 확인할 수 없으면 세그먼트를 종료하고 회복 뒤 새로 시작한다.
5. 일정 시간 이상 새 위치가 없거나, 계속 불량한 위치만 오면 즉시 `GPS 불안정` 상태를 알린다. 고정된 과거 페이스를 현재 페이스처럼 유지하지 않는다.
6. 짧은 보류 창을 두어 뒤따르는 관측으로 점프 여부를 판단할 수 있게 하되, 화면 지연은 제한한다. 보류 시간·정확도·속도·공백 임계값은 코드 상수로 흩뿌리지 않고 버전이 있는 설정으로 모은다.

구체적인 임계값은 먼저 저장된 실측 GPS와 합성 사례로 후보를 비교해 정한다. 기존 150m 정확도 상한을 정답으로 복사하지 않는다. 정해진 값과 이유를 테스트 결과와 함께 계획/검증 기록에 남기며, **3km 현장 시험 결과를 본 뒤 유리한 결과만 골라 합격 처리하지 않는다.**

### 3.2 거리·페이스의 불변조건

- 거리 증가분은 0 이상이며 누적 거리는 감소하지 않는다.
- 새 세그먼트의 첫 점, 공백 회복 첫 점, 일시정지 재개 첫 점의 거리 증가분은 0이다.
- 거리 증가분이 있으면 지도에서 같은 세그먼트의 두 점을 잇는 선이 존재한다. 지도에 선이 없으면 그 구간 거리도 없다.
- 지도 선의 길이 합과 앱의 측정 거리는 같은 경로점과 구간 경계에서 계산한다. 화면 장식용 평활화가 필요하더라도 거리와 의미가 달라지는 별도 경로를 만들지 않는다.
- 측정 구간 평균 페이스의 분모·분자는 동일한 유효 구간에서 나온다. 공백 시간만 포함하고 공백 거리는 빠지는 혼합 계산을 금지한다.
- 현재 페이스는 안정적인 최근 구간이 충분할 때만 표시하고, GPS 품질 불량·정지·일시정지 중에는 숨긴다.

## 4. Android 앱 구성

- Kotlin + Jetpack Compose의 독립 Android 프로젝트로 시작한다. 기존 프로젝트 파일을 대량 복사하지 않는다.
- Foreground location service가 고정밀 위치 업데이트를 수집한다. 권한 거부·대략적 위치만 허용·서비스 시작 실패를 사용자에게 명확하게 보여준다.
- 서비스가 화면 생명주기와 무관하게 수집·저장을 담당한다. 화면은 저장된 세션 상태를 관찰한다. 화면이 재생성되어도 세션은 유지된다.
- Room에 `RunSession`, `RawFix`, `PauseEvent`, 확정된 `TrackSegment`/경로점, 요약값과 계산 버전을 저장한다. 위치 콜백의 **배치를 먼저 영속화한 뒤** 경로 계산과 화면 갱신을 진행한다. 종료 시 계산 결과와 세션 상태를 트랜잭션으로 확정한다.
- 앱이나 프로세스가 죽으면 다음 실행에서 미완료 세션을 찾아 `비정상 종료 · 복구된 기록`으로 표시한다. 기록의 끝은 마지막으로 영속화된 관측 또는 세션 상태 이벤트 시점으로 잡는다. 원본은 보존하고, 실제로 관측하지 못한 종료 이후 시간·거리를 만들지 않는다.
- 지도 라이브러리는 구현 시작 시 Android/라이선스/타일 사용 조건을 재확인해 확정한다. 지도 위에는 세그먼트별 실선, 현재 위치와 정확도 표시, GPS 불안정 상태를 보여준다.
- 기록 상세는 원본을 다시 읽어 계산 버전을 확인할 수 있게 설계한다. 계산 방식이 바뀌어도 기존 결과를 자동으로 덮어쓰지 않는다.

## 5. 화면 흐름

1. **대기:** 위치 권한·정확한 위치 허용 상태, 현재 위치와 정확도, `달리기 시작` 버튼.
2. **측정 중:** 측정 거리, 경과 시간, 현재 페이스, GPS 상태, 지도, `일시정지`·`종료` 버튼. 신호 불량 시 현재 페이스는 숨기고 이유를 보여준다.
3. **수동 일시정지:** 시간과 거리 계산의 일시정지 범위를 명확히 표시한다. `재개` 시 새 경로 세그먼트를 시작한다.
4. **종료 요약:** 측정 거리, 경과 시간, 운동 시간, 측정 구간 평균 페이스, GPS 공백 개수/상태, 세그먼트별 지도.
5. **기록 목록·상세:** 저장된 값과 지도, 공백·복구 상태를 재표시한다.

## 6. 구현 순서

1. 새 Gradle/Android 프로젝트와 최소 화면·권한·서비스 뼈대 작성.
2. 원본 관측·세션·일시정지 이벤트 저장 및 비정상 종료 복구 구현.
3. 순수 Kotlin 경로 엔진과 재생 도구 구현. 정상 이동, 정지 잡음, 점프, 반환점, 긴 공백, 일시정지 경계 테스트 작성.
4. 서비스의 위치 콜백과 경로 엔진을 연결하고, 실시간 상태를 저장 결과에서 도출.
5. 지도·거리·페이스·상태 화면을 동일한 세그먼트 출력에 연결.
6. 기록 종료·상세·재실행 흐름을 연결하고 전체 빌드·테스트·실행 확인.
7. **첫 버전을 구현한 뒤** 3km 왕복 코스를 처음 달려 원본 GPS와 결과를 수집한다. 이 첫 실측은 문제 발견·조정용이다. 필요한 임계값과 로직을 수정한 후 **별도의 3km 재실측**으로 검증한다. 최초 시험과 재시험의 원본·계산 결과를 모두 남기고, 조정에 사용한 동일 기록만으로 통과 판정하지 않는다.

각 단계의 완료 조건은 코드 작성이 아니라 빌드·관련 자동 테스트 통과와 직접 실행 확인이다. 복잡한 변경을 마친 뒤 별도 검증 에이전트가 경로 엔진과 서비스·저장·UI 경계면을 독립 검토하고, 지적한 문제를 수정·재검증한다.

## 7. 검증 계획과 통과 기준

### 7.1 자동 검증

- 거리·지도 불변조건: 세그먼트 경계를 가로지르는 선/거리 0건, 지도 선 길이 합과 기록 거리의 일치.
- 합성 트랙: 직선·코너·왕복·정지 10분·점프·GPS 공백·일시정지·재개·순서 뒤바뀐 배치.
- 기존 앱에 보관된 2026-07-26 원본 GPS 1,118점은 **회귀 사례**로 사용한다. 이 기록은 걷기이므로 달리기 정확도의 합격 근거로 사용하지 않는다.
- 저장·복구: 수집 중 강제 종료, 마지막으로 영속화된 관측까지의 복구, 비정상 종료 시각의 확정, 앱 재시작, 완료 기록 조회, 계산 버전 보존.
- Gradle 단위 테스트·빌드 통과 후 Android 기기에서 시작부터 종료·기록 조회까지 실행.

### 7.2 실기기 시험

사용자가 예고한 **왕복 3km 코스**를 기준으로 한다. 먼저 앱의 첫 버전을 만든 다음 시험한다. 출발·반환·도착 지점을 미리 정하고, 실제 코스 길이의 근거와 휴대폰을 손에 들었는지/주머니에 넣었는지 기록한다. 최소한 코너·반환점이 지도에 남는지 확인한다. 가능하면 별도로 10분 정지, 화면을 끈 30분 기록, 신호가 가려지는 구간도 시험한다. 손과 주머니 조건은 한 번의 기록으로 동시에 검증하지 않는다. 첫 기록으로 계산 규칙을 조정했다면 독립적인 재실측을 통과 기준에 사용한다.

| 조건 | 통과 기준 |
|---|---|
| 거리가 알려진 2~5km 코스, 수신 양호 | 측정 거리 오차 ±5% 이내. 3km에서는 2.85~3.15km. |
| 같은 조건에서 휴대폰을 주머니에 넣음 | 측정 거리 오차 ±10% 이내. 3km에서는 2.70~3.30km. |
| 제자리 정지 10분 | 측정 거리 증가 20m 미만. |
| 코너·왕복 | 반환점과 진행 방향이 보이고, 고립된 GPS 점프를 실선으로 잇지 않음. |
| GPS 공백·수동 일시정지 | 공백을 실선으로 잇지 않음. 공백 앞뒤 직선거리 증가 0m. 기록에 공백 표시. |
| 화면을 끈 채 30분 | 기록이 유지되고 종료 후 경로·거리를 조회할 수 있음. |

거리 오차 수치는 GPS가 실제로 충분히 관측된 세션에서 평가한다. 수신이 길게 끊긴 세션은 `측정 불완전`으로 보고하며, 실제 총거리를 맞춘 것처럼 통과시키지 않는다. 수신 양호/불량의 구분 기준은 **시험 전에** 정확도·연속 관측률·공백 길이로 명시하고, 모든 세션의 원본과 판정 결과를 함께 보관한다. 기준 미달 시 원인을 분석하고 재시험하기 전에는 위치 정확도 검증이 끝났다고 보고하지 않는다.

## 8. 완료 산출물과 한계

- 새 프로젝트 소스, 로컬 저장 스키마, 경로 엔진, 화면, 자동 테스트, GPS 재생 도구, 빌드·실기기 검증 기록.
- 사용자에게 보이는 거리의 의미와 GPS 공백 처리 규칙을 앱과 문서에서 일치시킨다.
- GPS가 없는 동안 실제로 지난 길은 복원할 수 없다. 해당 구간의 정확한 총거리 제공은 목표에 포함하지 않는다.
- 이 문서는 구현 계획이며, 현재 `running2`에는 앱 코드가 없다. 구현·실기기 측정 결과는 아직 없다.
